# Быстрый тест: Wi-Fi 2,4 ГГц на тех же платах T-HaLow (09.10)

Зачем: задание требует сравнить Wi-Fi HaLow с IEEE 802.11 «на идентичной аппаратной
платформе». До теста для Wi-Fi был только расчёт по паспорту ESP32-S3. Здесь тот же
видеопоток идёт через встроенный Wi-Fi ESP32-S3 той же пары плат, а приёмник отдаёт его в
тот же `halow_viewer.py`, поэтому столбцы CSV совпадают с HaLow-прогонами.

## Что одинаково и что нет

| | HaLow (итоговая версия 08.10) | Wi-Fi 2,4 ГГц (этот тест) |
|---|---|---|
| Камера, разрешение, сжатие | OV5640, 480×320, RGB565 → JPEG программно, Q70 старт | то же, Q70 фиксированно (`q`) |
| Частота кадров | до 5 к/с | до 5 к/с (`f`; `f 0` — без предела) |
| Куски, заголовок, CRC кадра | 1400 Б, `HLW2` | то же |
| Роли | камера — точка доступа, приёмник — станция | то же |
| Мощность | регулятор 1–14 дБм | фиксированная, по умолчанию 14 дБм (`p`) |
| Квитанция и RTT | на каждый кадр | на каждый собранный кадр |
| Надёжность | FEC + досылка + повторы MAC | только повторы MAC |
| Канал | 2 МГц, 867 МГц | 20 МГц, канал 6 (`WT_CHANNEL`) |

## Прошивка

В `platformio.ini` раскомментировать по очереди (после смены `src_dir` — clean):

```
src_dir = examples/WifiVideoTest_CAM   ; плата с камерой
src_dir = examples/WifiVideoTest_RX    ; приёмная плата
```

Режим физического уровня — `WT_PROTO` в `lib/WifiTest/wifi_test_common.h`, одинаково на обеих
платах: 0 — 802.11b/g/n, 1 — только 802.11b, 2 — Espressif LR. Канал — `WT_CHANNEL`
(выбрать наименее занятый из 1, 6, 11). Модуль TX-AH в этом тесте молчит: скетчи его не трогают.

## Запуск

Приёмник — к ноутбуку, камера — от powerbank, как в HaLow-прогонах:

```
python tools/halow_viewer.py --serial-video COM7 --csv --note wifi_5m_14dbm
```

Камера пишет раз в 5 с строки `[связь] … fps …`, `RTT ср … мин … макс …` и
`WIFI rssi=… nf=… snr=… pwr=…` — они попадают в лог по воздуху и в CSV (`air_rssi`,
`rx_snr`, `pwr_dbm`, `cam_nf`, `rtt_*`). Приёмник кладёт свой уровень сигнала и фон в
`ap_rssi` и `ap_bgr`.

## Порядок опыта (полдня)

На каждой точке — по 2–3 минуты HaLow и Wi-Fi подряд, без перестановки плат, с меткой в окне
просмотрщика (например `wifi 5m 14`):

1. **5 м, 14 дБм** у обоих — база: скорость, кадры в секунду, потери видеокадров, RTT, RSSI.
2. **Wi-Fi 20 дБм** (`p 20` на обеих платах) — разрешённый максимум для 2,4 ГГц.
3. **Пропускная способность**: `f 0` — камера шлёт без предела, видно потолок канала.
4. **Фон у платы с камерой**: столбец `cam_nf` с камерой в работе. Сравнить с фоном приёмника
   (`ap_bgr`). Это ответ на вопрос, мешает ли плата с камерой Wi-Fi так же, как HaLow.
5. **Ослабление**: те же пары замеров за одной и двумя стенами, в конце коридора, в соседнем
   помещении; затем ступени мощности 20 → 14 → 8 → 2 дБм на каждой точке. Где Wi-Fi теряет
   видео, а HaLow ещё держит (или наоборот) — это и есть результат сравнения.

## Чем обработать

CSV обоих прогонов лежат в `tools/logs/`. Для сравнения достаточно средних по метке:
кадры в секунду, полезная скорость, доля потерянных видеокадров, `rtt_avg`, `air_rssi`.

## Оговорки

- `nf` берётся из служебного поля принятых пакетов ESP32-S3 (режим promiscuous). Единицы по
  документации — дБм; если в первом прогоне выйдут числа ниже −150, это 0,25 дБм и их надо
  делить на 4.
- Без FEC и досылки Wi-Fi теряет видеокадр при потере любого куска, HaLow-версия часть таких
  кадров спасает. Это нужно указать при сравнении потерь.
