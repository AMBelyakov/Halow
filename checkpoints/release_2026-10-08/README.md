# Релиз — 08.10.2026: видео Wi-Fi HaLow между двумя платами T-Halow

Камера (плата А, ESP32-S3 `20:6E:F1:A7:D4:28`, ползунок модуля **AP**) снимает, сжимает и шлёт
видео по Wi-Fi HaLow 867 МГц. Приёмник (плата Б, `9C:13:9E:B5:B3:C0`, ползунок **STA**) отдаёт
его по USB на ноутбук в просмотрщик. Код заморожен; дальше — замеры на дальности.

**Итог на 5 м (08.10 02:31–02:34):** 1063 кбит/с полезного видео, 5 к/с, 480×320, потеряно 1,4 %
кадров, мощность передатчика 1 дБм, перезапусков 0.

## 2. Что сделано

### Канал и транспорт

| Что | Как | Эффект |
|---|---|---|
| Видео через прозрачный UART модуля | протокол HalowVideo: кадр режется на куски по 1400 Б, у куска заголовок, у кадра CRC; UART ESP↔модуль 3 Мбод | основа всего |
| Доставка на ноутбук по USB приёмника | приёмник отдаёт куски в USB, кадры собирает просмотрщик | RJ45 не годится: мост модуля не выпускает данные в сеть |
| Связь поднята | запас порога CCA 20 дБ на точке доступа (`AT+BGRSSI_MARGIN=20`) | 28.08: без него ассоциация не проходила |
| Законный канал | 2 МГц на 867,0 МГц (`BSS_BW_SET 2`, `CHAN_SET 8670`) | в пределах ГКРЧ 866–868 МГц |
| Кольцо приёма UART в модуле ×4, таймер тишины 2 мс → 400 мкс | сборки модуля 24.09 и 29.09 | модуль перестал терять куски на входе |
| Пауза после куска 1,5 мс | `CHUNK_GAP_US 1500`, подбор 0,6–2,0 мс | максимум скорости без битых кусков |
| RTS/CTS выключен | `AT+SET_RTS=1000` в стартовом окне | ×1,8–2 к скорости (29.09) |
| Камера — точка доступа, приёмник — клиент | смена ролей ползунками | 05.10: «всем» от клиента шло хуже |
| Окно кадров W=4 + квитанции | квитанция на кадр: какие куски дошли, RTT | поток без простоев, мерка задержки |
| Регулятор мощности в модуле | `AT+PWRCTL`: SNR, с которым слышит сосед, держится в 20–30 дБ, шаг 2 дБ, потолок 14 дБм | вблизи 1 дБм (нет радуги), на дальности — до предела ГКРЧ |
| Модуляция широковещательных кадров по SNR | `AT+MCSCTL` в модуле | маяки и широковещание — по уровню сигнала |
| **Пол MCS по уровню сигнала** | `AT+MCSFLR` в модуле: при SNR ≥ 22/18/14/10 дБ повторы не ниже MCS 4/3/2/1, пропала связь — пол снят | +48 % скорости и вдвое меньше потерь против «пол снят» в одном включении; дальность не режется |
| **Гибрид FEC + досылка** | контрольные куски XOR с подбором их числа (0–8) по квитанциям + однократная досылка пропавших кусков (кадр моложе 1,5 с) | потеряно кадров 2–3 % вместо 10–12 % |
| Короткая квитанция v3 'HLWB' | 20 байт тела | пакеты приёмник→камера длиннее 27 Б до камеры не доходят |

### Камера

| Что | Как | Эффект |
|---|---|---|
| Съёмка в RGB565 + программное сжатие | аппаратный JPEG OV5640 зависает | стабильный захват |
| Сжатие esp_new_jpeg 1.0.2 на двух ядрах | `NEW_JPEG 1`, два кодировщика | QVGA 62–68 мс вместо ~150; открыло 480×320 |
| Кадр 480×320 | `FRAMESIZE_HVGA` | больше деталей при той же скорости канала |
| Ток выходов сенсора ×1 | регистр OV5640 0x302C (`CAM_DRIVE 1`) | кадр легче на 13–18 %, нет зависаний захвата |
| Фильтр VSYNC 7, буферы кодировщика во внутренней памяти | `CAM_VSYNC_FILTER 7`, `ENC_BUF_INTERNAL 1` | нет переполнений DMA, 6,5–7,6 к/с |
| Правка «слипа» (радуги) | поиск и исправление сдвига байта в кадре | радуга устранена без пайки |
| Паузы съёмки при большой мощности | `GATED_CAPTURE`: от 8 дБм съёмка в паузах передачи | нет радуги от наводки передатчика |
| Сторож камеры | 2 пустых перезапуска драйвера → перезагрузка ESP; счётчик VSYNC/HREF (PCNT) | захват не встаёт навсегда |
| Автокачество (правила 4) + предел к/с | качество JPEG по медиане задержки квитанций, не меньше 4–5 к/с | качество под канал |
| **Инерция автокачества** | потолок качества после затора на 30–120 с, вверх шагами по 5, досрочное снятие на свободном канале | +35 % скорости, задержка вдвое ниже, потерь вчетверо меньше |
| **Смена разрешения на ходу** | 480×320 → 320×213 → 240×160 ниже Q30, обратно с Q80 | видео не встаёт на плохом канале |
| **Одна прошивка на все расстояния** | регулятор мощности 1–14 дБм + паузы съёмки сами от 8 дБм | не надо перешивать в поле |
| Лог камеры по радио | текст камеры идёт кусками 'T' в просмотрщик | видно, что делает камера, без провода |

## 4. Что проверено и отвергнуто

| Идея | Почему отвергнута |
|---|---|
| Доставка через RJ45 (Mode2) | мост модуля не выпускает данные в сеть; для БПЛА нужен был бы «летающий ноутбук» |
| Аппаратный JPEG сенсора | зависает |
| Разгон такта сенсора (PLL), XCLK 16 МГц | переполнения DMA или 99 % кадров со сдвигом байта |
| Ток выходов сенсора ×4 (как в библиотеке) | +20 % байт кадра от шума, зависания захвата |
| 14 дБм прибито | радуга почти в каждом кадре; заменено регулятором |
| Регулятор мощности с коридором 25–35 дБ | вблизи залез на 14 дБм и застрял; заменён коридором 20–30 |
| Широковещание от камеры-клиента | клиент отдаёт его точке адресно с повторами — хуже адресного |
| Выключить склейку пакетов, удлинить ожидание ACK, автосклейка | без эффекта |
| `AT+RC_NEW=1` (другая цепочка выбора модуляции) | +3 %, две перезагрузки модуля из трёх включений |
| Прибитая модуляция MCS 7 | быстрее вблизи, но рвёт связь на дальности |
| Постоянный пол MCS 4 / 5 | 4: +19 %, но режет дальность; 5: хуже. Заменён полом по уровню |
| Меньше повторов в модуле (`AT+TX_CNT_MAX` 1–2) + сильный FEC | треть первых передач правда теряется: 1 попытка — 38 % потерь, 2 — 18 %; выигрыш съедается избыточностью |
| Прибитая избыточность FEC (4 контрольных куска) | лишняя нагрузка сама поднимает потери (до 6,8 %) |
| Приём UART в модуле через DMA, UART 4,8 Мбод | процессор модуля простаивает 92–93 %, UART не упор |
| Задержка «стекло-стекло» | решение пользователя: метрика не нужна |
| H.264 вместо JPEG | решение пользователя: не нужен |
| esptool 4.11 для заливки | не помог; виноват USB камеры |

## 5. Что не сделано и что известно

| Что | Состояние |
|---|---|
| Замеры на дальности (скорость, потери, RSSI по меткам расстояния) | главное, что осталось: подъём мощности, паузы съёмки (≈2 к/с на 14 дБм) и снятие пола проверяются только в поле |
| Почему ~1/3 первых передач теряется при сильном сигнале | не найдено; версия — шум платы камеры (фон −60 дБм против −87 у приёмника), паять нельзя. Это и есть потолок ~1 Мбит/с |
| Статистика модуля приёмника | не сделана; нужна, только если в тексте ВКР понадобится объяснить потери строже |
| Приёмник сам не переподключается после перезапуска камеры | ограничение железа: линии сброса модуля на плате нет — приёмник передёргивать вручную |
| USB камеры разболтан | заливка ESP только кусками, с удержанием BOOT; модуль — только прошивальщиком |
| Подбор числа контрольных кусков FEC дёргается (20 смен за 6 мин) | инерция подбора не сделана; на 5 м подбор и так держит 0 |
| Зависания захвата камеры | были только на токе ×4; на ×1 не повторялись, корень не найден |
| Git | закоммичено 08.10 (коммит `all`) |
| PER модуля 50–67 % на 5 м | это доля неудачных попыток радио (повторы, пробы, пачки без Block-ACK), а не потери видео; в релизном прогоне потеряно 1,4 % кадров. См. журнал, «08.10: что считает PER» |
| `examples/HalowVideoP2P_STA` ≠ релиз | рабочая копия скетча камеры отличается от `src_camera/` пятью настройками: `ROLE_SWAP 0`, `PWRCTL_LO/HI 25/35`, `TX_POWER_DBM 14`, `VAR_SWEEP_NS`. Шить камеру из `src_camera/` или готовым образом |

## 6. Как залить и запустить

ESP32 камеры — кусками, с удержанием BOOT:

    python -u tools/flash_parts.py --part-kb 16 --serial 20:6E:F1:A7:D4:28 --file checkpoints/release_2026-10-08/camera_HalowVideoP2P_STA_release.bin

Ползунок на STA, кабель передёргивать со стороны ноутбука, BOOT держать ~10 с после втыкания;
срыв — повторить, заливка продолжится с непроверенного куска.

Модуль камеры (если понадобится заново): залить `esp_module_updater_mcsflr.bin` так же, передёрнуть
без BOOT — ESP сам передаст образ модулю (~70 с, светодиод мигает, потом гаснет) и запомнит успех;
затем залить обратно скетч камеры.

Запуск: камера ползунок AP, питание от ноутбука или powerbank; через ~10 с воткнуть приёмник
(ползунок STA). После любого перезапуска камеры передёрнуть приёмник. Просмотрщик:

    python tools/halow_viewer.py --serial-video COM7 --csv --playout-ms 700 --note <метка>

Страница — `http://localhost:8099`, метки расстояния — `100m` + Enter, остановка —
`http://localhost:8099/quit`.
